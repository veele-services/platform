## Securityhardening versus visuele scope

Het pakket schrijft geen onnodige v2-brandingschemaherbouw voor. Wel geldt:

- er komt geen schemawaarde voor UI-versieselectie en geen duplicatie van
  kleur-, font-, radius-, density- of e-mailvelden;
- W01 voert de afzonderlijk gecontracteerde forward migration uit voor
  `logo_mode`, `favicon_mode`, `splash_mode`, monotone `theme_revision` en de
  immutable document-appearance-snapshots; lege-DB-, upgrade-, backfill-,
  rollback- en tenantisolatietests zijn releasebewijs;
- een visuele PR mag geen bestaande securityfout maskeren;
- W00 controleert de effectieve deployed policies, niet alleen migratiebestanden;
- bevestigde P0-policy-, storage-, domain-, SSRF- of RBAC-fouten krijgen een afzonderlijk hardeningwerkpakket;
- zo’n pakket heeft eigen migration-, backup-, rollback- en tenantisolatiebewijs;
- Fieldflow global rollout wacht daarop.

## Risicosluiting

Toegestane, cumulatieve volgorde: `OPEN → MITIGATED → VERIFIED_LOCAL → VERIFIED_STAGING → CLOSED`. Een state mag niet worden overgeslagen. `OPEN` claimt geen evidence. Vanaf `MITIGATED` wijst `{commit,index}` naar dezelfde gehashte v2-index als het acceptancecontract, met `verification=risk-mitigation`, werkelijk gewijzigde PR-bestanden, vaste commands, een geattesteerd machineleesbaar runtimerapport, nul failures/skips/errors, Git-ancestry en live succesvolle GitHub Actions-provenance. Local voegt een onafhankelijke live exact-HEAD `APPROVED` GitHub-review toe; staging voegt het geattesteerde stagingrapport en afzonderlijke live `functional-security`- en `visual-a11y`-reviews toe. `CLOSED` bewaart `residualRisk` en `closureDecision` in de index. Iedere state boven `OPEN` vereist daarnaast dat de volledige digestvector exact overeenkomt met de extern geregistreerde beschermde contract-root en dat de base-eigen statuscheck groen is. Een hash, handmatige bewering, zelfverklaarde reviewer of onbereikbare API promoveert niets. De handoffsnapshot start terecht met alle items op `OPEN`; globale promotie is geblokkeerd zolang ook maar één item niet `CLOSED` is.

Een item is alleen gesloten met:

```text
status
eigenaar
exacte commit + subject-/HEAD-gebonden indexhash
Git-bestandspaden + blobhashes
commands met status `passed` en exitcode `0`
runtime- en stagingartefacten + SHA-256
onafhankelijke functioneel/security- en visual/a11yreviewers zonder self-review
residueel risico + sluitbesluit in de index
```

“Bestaande test is groen”, “UI verbergt de knop” of “alleen Enterprise” is geen sluitbewijs voor een server-/tenant-/securityrisico.
